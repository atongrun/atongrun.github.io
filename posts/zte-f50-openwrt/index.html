震惊，中兴 F50 竟然能刷 Openwrt，我的随身 wifi 变成了软路由，焕发第二春！

01 Nov, 2026

好早之前搬家，因为拉宽带太贵了，想着后续搬家也不方便，就打算买个随身 WiFi。

我倒是看了不少的测评，判断不出来有没有坑，小红书好多就觉得有点不靠谱，都像是广告，索性直接买了个大牌中兴。

贵是贵了点，但整体还是靠谱的。当时还写了篇自己的测评发到了微信公众号：中兴随身wifi使用体验 (https://mp.weixin.qq.com/s/DQFhVQTTnXedZH0crX-uvw)

F50整体还算不错，但是 F50 有一个大缺点，就是散热太差了，必须再买个散热套件，加上散热套件之后，用起来就挺顺心了，工作温度不超过50，但这个带来了另外一个问题，就是便携性就差了不少

其实在我我买的时候，F50还有一个隐藏的“缺点”，就是他的系统还是比较封闭的，不能刷别的系统，虽然日常使用没有什么大影响，但是对想折腾刷个OpenWrt的用户来说，还是少了些乐趣，毕竟还是连个wifi 就能畅游世界的感觉还是比较爽的

但是，但是，没想到一年多后的今天，我刷到一个帖子，有大神做出了整套的刷机工具，然后开源到了 github

我的这个中兴 F50，是256GB 存储版。平时插着 SIM 卡当随身 Wi-Fi，用起来没什么问题。看到有人把 F50 装成 OpenWrt，还保留 Android 双系统，我就心里痒痒的，想着直接让codex给我也刷一个得了，没想到实际操作起来到处是坑

想入手同款的话，这是我放在自己小站上的京东链接：中兴 F50（京东）。F50 有好几个容量版本，下单前看清楚，想刷机的话不同容量的分区情况不一样，后面会说到。

Codex 看文档、查设备、跑命令、翻日志，我打辅助，拔插设备、拿手机测网。10 月 7 日开始弄，一直拖到 10 月 10 日才算能正常上网。

256GB 的机器，愣是没地方装 OpenWrt

我是直接复制了一段网上现成的提示词给 Codex，我也没细看，里面其实写了一句"已插入一张可以清空的 SD 卡"

但我的F50没有 SD 卡，聊到装在哪的时候才反应过来这句不对。

而且更吓人的是，F50 在 Windows 里挂了个 228GB 左右的共享盘，Codex 差一点要把它整个备份一遍，还好我机智，多问了一句

最后让codex 直接装进去得了，我的F50是存储版本，256GB 呢，里面也没存啥东西。

安装开始时一查分区表，差点又搞错，项目作者常用的参考机是 64GB 的 F50，那台在 Android 分区后面本来就留着一块空地，Linux 直接放进去。

但是我的这台是 256GB 的，Android 的数据分区一路占到快到磁盘末尾，Windows 的共享盘就是从这块空间里共享出来的，Codex一直给我搞不定了就

我就很生气，质问codex，都是 F50，就 Flash 大小不一样，凭啥不能通用？

我问完codex 才意识到系统本身可能是通用的，它又巴拉巴拉出方案，最后我同意了codex出的一个方案，就是清空 Android 数据，从 userdata 末尾切出大概 4GiB 给 OpenWrt。

动手之前先备份了系统分区、分区表和 NV、校准这些本机专属的数据，加起来 5.86GiB 左右，应用和个人文件就没管了。

分区切完，我以为地方总算有了，Codex 又查出一个问题：userdata 分区已经缩到约 224.19GiB，但里面的 F2FS 文件系统还以为自己有原来的约 228.19GiB。分区边界改了，文件系统压根不知道，这时候往后面装 OpenWrt，而且怕哪天 Android 写数据就写到 Linux 头上去了。

codx说完，我人都傻了，当时心里一群🐎飞过，一个破随身wifi还整存储版本256G的，比普通版本的贵好多，实际这个空间我也用不上，想装个软路由还状态频出～

作者流程里那步清零在我这台上没起作用，只好再确认一次清数据，用作者下载工具里对应的 Recovery 恢复出厂，让它按新分区重建文件系统。弄完再看，两边都是 224.19GiB，最终对上了，才敢接着装。

先让电脑管得了它：ADB 和 Root

回过头说，前面查分区表、切分区、看 F2FS，说起来挺顺，其实都有个前提：电脑得先能"管"到 F50。这一关是在切分区之前过的，放到这里单独说。

管它靠的是 ADB，大白话讲，就是电脑通过 USB 给安卓设备下命令、做调试的通道。F50 里面跑的就是 Android，Codex 要查分区、读日志、写镜像，全得走这条路。光有 ADB 还不够，改分区表、动系统分区这些，还得有 Root，也就是设备的最高管理员权限。这两样没有，Codex 什么都查不了，也改不了。

ADB 这关就卡了我一会儿。电脑能认出 F50，adb devices 却是空的，电脑上弹的授权也点了，没用。原厂后台菜单里翻了一圈也没有 USB 调试，最后是在这个页面打开的：

http://192.168.0.1/index.html#usb_port

登录，选打开，点应用，ADB 就出来了。不过这是我这版固件有的页面，别的版本有没有我也不知道。

连上一看：F50 / MU300，板型 ums9620_2h10_feimao，原厂固件 F50SPV1.0.0B06，Android 13。没 Root、没解锁，ADB 我也是头一回用。

能连上只是第一步，接下来是拿 Root。先试了原厂的 fastboot flashing unlock，没成。后来按作者工具包的配套流程走，换了配套的系统、启动链和基带镜像，再写 TrustOS 和 Magisk。这么一折腾，Android 从 B06 变成了工具包配套的 B09。所以那句"只写 B 槽"别太当真，为了拿 Root，前面已经动了不少东西。

Magisk 还坑了一下，镜像写进去了，配套的运行文件没有，Root 实际用不了。补上官方 28103 的运行环境，再给 ADB shell 开了 Root 权限，跑一句

su -c id

看到 UID 0，这才放心往下改分区，也就是前面说的切 userdata、重建文件系统那一串。

Wi-Fi 搜得到，手机就是连不上

Root 有了，分区和文件系统也对上了，终于轮到装 OpenWrt 本身。装的是带 MU300 管理面板的 OpenWrt 25.12.5（项目 v2026.10.11），厂商的 5.4.254 内核。Android 留在 A 槽，Linux 在 B 槽，原来的 Wi-Fi 名称和密码也搬了过来。

第一次开进 OpenWrt，手机能搜到熟悉的 Wi-Fi，一点连接，失败，设备还亮着红灯。电脑那边有时能拿到地址，后台却打不开，SSH 也进不去。

后台和 SSH 都进不去，只能看串口日志，最后在里面看到防火墙报错：

flowtable ft: Resource busy
flow offload @ft: No such file

5.4 内核跟软件流量加速（flow offloading）合不来，防火墙重载失败，LAN 的规则没加载全。把软件流量加速关了，重新加载防火墙就好了，防火墙本身还开着。

手机终于连上了，后台、SSH 都能进。我当时心里想，卧槽，花了我这么多时间精力token，用着最好的Astra，这次应该终于OK了，没想到：打开网页，没网。

有信号、有 IP，就是没网

人的心态就是这么一次又一次的搞炸的，Wi-Fi 是连上了，可连上之后没网，这一段磨了我两天，还影响我正常用wifi

所有的状态：注册上运营商了，拨号返回 CONNECT，WAN 有 IP，路由也有。可蜂窝网卡的接收计数一直是 0，DNS 没回应，网页打不开。切回 Android，同一张卡立马能上网，那硬件和套餐肯定没毛病，问题在 Linux 这边。

中间还短暂通了一下，搞得我更糊涂了。之后再测，我都先关掉手机的移动数据，电脑也指定走 F50 的 USB 网卡，免得从别的网络绕出去。

既然 Android 能上，Codex 就去对照 Android 是怎么跑的，发现项目脚本默认用的是 nr1/nr2 通道和 sipa_eth0 网卡，而我这台 Android 实际把卡放在逻辑 slot 1，数据网卡是 sipa_eth8，AT 命令走 nr4。我当时还嘀咕，我插的明明就是实体卡啊。可实体卡插在哪，跟基带给它编的是几号卡槽，根本对不上号，只能看机器实际怎么跑。

照着改的时候 Codex 还手滑了一次，把 SMMSWAP 的参数当成卡槽号改了，AT 直接出错，后来查了原厂的用法才改回 AT+SMMSWAP=0。

改完，识别、注册、拨号都正常，接收计数还是 0。

接着又查驱动、查路由、查有没有 VPN 留下的规则，照原厂顺序配 PDP，还试了一次 AT+SPSWITCHDATACARD=1,1，回了个 CME ERROR: 4。全都没用。

折腾到 10 月 8 日晚上，我说最后再试一次，不行就先切回 Android，设备我还得用，周末再整。果然不行，让 Codex 切回 Android、设成默认启动，手机和电脑都测了能上网，这才收工。

真是有点崩溃了，没想到F50 这么难刷机

到了周末，我第一句就是：先去网上看看有没有人解决了，没有再自己研究。

这回运气不错，mu300-linux 仓库里有个 PR #72，症状跟我的几乎一样：slot 1 拿到地址，拨号 CONNECT，就是收不到回包。提交者发现原厂系统拨号后还会多发一条：

AT+SPSWDATA

用来设置数据路由。跟前面失败的那条 SPSWITCHDATACARD 名字很像，是两条不同的命令。

那时候这个 PR 还是草稿，Codex 没把整个分支刷进来，先在我这台 B09 的原厂系统里确认确实有这条命令，再在现有的 OpenWrt 上手动发了一次。

返回 OK，接收计数从 0 跳到 81，DNS 马上有回应，电脑打开百度、腾讯都正常。关掉手机流量连 F50 的 Wi-Fi，也能上了。

还有一件事，我配的 APN 是 cmnet，基带返回的却是 cmiot5g，我一度怀疑是 APN 配错了。社区记录里说 Android 正常上网时也是这样，就没再管它。

手动能通还不够，得让它开机自己来。Codex 把这条命令加进了拨号脚本：拨号确实返回 CONNECT 才发 AT+SPSWDATA，收到 OK 才算拨号成功。

然后重启测。普通重启，五十秒左右网就回来了。又拔了 USB，等十秒插回去，让它自己开机，手机照样能上，电脑走 USB 也正常。这下我才敢说装好了。

终于能上网了，再把 Clash 塞进去

网通了之后我又贪心了一下，让 Codex 读我电脑本地的订阅文件，在 F50 上配 Clash，国内直连，其他走代理。这样手机电脑连上 F50 就行，不用再各自开客户端。

节点用的是我自己在 DediOne 洛杉矶（CMIN2 / CUII 线路）那台小机器上搭的，同款套餐在这：DediOne 移动联通精品，有特价款和常规款，端口和流量不一样，买之前看清楚。

装的是 Mihomo（Clash Meta）v1.19.32 ARM64，加一个本地管理面板。作者后来出的代理模块要求更新的系统版本，我没为了这个整机升级，怕把好不容易修好的 SIM1 脚本覆盖了，Mihomo 就单独装。

装好先不接管流量，单测节点，Google、YouTube、百度都能开，再打开 TUN。结果 5.4 内核又来了一次：开 auto-redirect 报 Netlink 不支持。最后换成普通的 TUN 策略路由，补一条 LAN 到 TUN 的防火墙转发，搞定。

关了手机流量和手机上的 VPN 测，国内国外都正常，重启后也没问题。10 月 11 日我又问能不能升级，一查 v1.19.32 已经是最新稳定版，那就不动了。

折腾完，它终于成了我想要的软路由

前前后后折腾完，现在 F50 默认进 OpenWrt，手机连 Wi-Fi、电脑插 USB 都能上网，分流也交给它了，断电重启自己恢复。Android 还在，想用随时切回去，Linux 连续五次没开起来也会自动退回 Android。

这次没 Codex 我大概率早放弃了，那么多文档和日志，我自己真看不过来。当然它也没少走弯路，我自己也给错过信息。

详细记录和检查脚本放在 GitHub：f50-256g-openwrt-guide，同款 256GB 想折腾的可以参考，分区、固件、卡槽记得按自己机器查。

最后再次感谢 mu300-linux 的作者和社区
